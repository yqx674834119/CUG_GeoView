# 时序跟踪数据集与公开模型调研

更新日期：2026-04-08

本文只聚焦你指定的 5 套数据：

1. VISO
2. SatVideoDT
3. OOTB
4. VisDrone: Multi-Object Tracking
5. A2Seek

调研目标是回答两件事：

1. 有没有公开模型 / 公开代码 / 公开权重
2. 官方公开的精度指标是什么

## 1. 总结结论

如果按你的目标

1. `MOTA >= 0.70`
2. `IDF1 >= 0.70`
3. 异常事件检出 `Precision >= 0.65`

来选数据集，建议这样理解：

### 最适合做主评估的

1. **SatVideoDT / VISO**
   - 原因：官方就有卫星视频多目标跟踪任务，并且明确用 `MOTA / IDF1`

### 最适合做补充回归的

1. **OOTB**
   - 原因：卫星视频，但它是单目标跟踪，不适合做你的 `MOTA / IDF1`

### 最适合做工程联调的

1. **VisDrone-MOT**
   - 原因：数据公开、下载方便、工程生态成熟
   - 但缺点是它不是卫星视频，而且官方 challenge 主指标并不是 `MOTA / IDF1`

### 最适合做预警模块验证的

1. **A2Seek**
   - 原因：它有异常类别、时序区间和区域框
   - 但缺点是它不是卫星视频，也不是 MOT 数据集

### 在当前机器资源约束下最适合下载测试的

1. **A2Seek_Preview**
   - 原因：官方 Hugging Face 预览集公开可下
   - 公开元数据总量约 `200.57 MB`
   - 适合先验证“时序输入 + 结果输出 + 预警可视化”链路

2. **WALDO30 轻量权重**
   - `WALDO30_yolov8n_640x640.pt` 约 `6.00 MB`
   - 适合做 BoT-SORT 的检测器侧工程联调

3. **SatVedioDTkit**
   - 体量小，适合作为评估与格式转换工具补充
   - 但它不是测试图像数据

## 2. 分项调研

## 2.1 VISO

官方入口：

1. 数据集仓库：<https://github.com/QingyongHu/VISO>

官方页面确认的信息：

1. 官方 README 写明这是卫星视频检测与跟踪数据集
2. 数据规模为 `40` 个卫星视频
3. 共标注 `853,911` 个实例
4. 目标类别包括 `plane / car / ship / train`

### 是否有公开模型

官方数据集仓库本身：

1. 提供公开数据下载
2. 提供 benchmark 说明
3. **没有在 README 中直接给出官方 baseline 权重下载**

### 公开代码 / 权重情况

与 VISO / SatVideoDT 强相关的公开模型里，最值得关注的是：

1. MP2Net 官方仓库：<https://github.com/DonDominic/MP2Net>

MP2Net README 明确公开了：

1. 官方代码
2. `model weights`
3. `raw results`

### 官方/公开指标

VISO 自身 README 主要提供数据介绍，没有直接给出 `MOTA / IDF1` baseline 数字。

但 VISO 被 SatVideoDT challenge 直接作为基础数据集扩展使用，因此 VISO 的正式 MOT 指标通常参考 SatVideoDT。

### 适合程度

1. 与你的目标非常匹配
2. 是目前最该保留的一套主数据

## 2.2 SatVideoDT

官方入口：

1. 挑战页：<https://satvideodt.github.io/>
2. 官方工具仓库：<https://github.com/zf020114/SatVedioDTkit>

官方页面确认的信息：

1. Track 1 是 moving object detection
2. Track 2 是 single object tracking
3. Track 3 是 multi-object tracking
4. Track 3 明确以 `MOTA` 和 `IDF1` 作为最终排序指标

### 官方 baseline

SatVideoDT 官方页面直接给出了 baseline：

1. Detection baseline：`DSFNet`
   - `mAP@0.5 = 0.43`
2. Single-object tracking baseline：`CFME`
   - `DPR = 0.504`
   - `OSR = 0.282`
3. Multi-object tracking baseline：`SORT`
   - `MOTA = 0.418`
   - `IDF1 = 0.389`

这组数字是目前这 5 套数据里，与你目标指标定义最一致的一组官方公开数字。

### 是否有公开模型

官方 challenge 页面：

1. 给出了 baseline 名称和指标
2. 给出了工具仓库
3. **没有在 challenge 页直接放出 baseline 权重下载**

但 SatVideoDT 生态里已经有公开模型：

1. MP2Net 官方仓库：<https://github.com/DonDominic/MP2Net>

MP2Net README 明确写明：

1. 在 `SatVideoDT` 上达到 `66.9% MOTA / 76.0% IDF1`
2. 同时公开代码、模型权重和 raw results

### 判断

1. **如果你要做正式 MOT 主评估，SatVideoDT 是优先级最高的数据**
2. 公开模型可直接参考 MP2Net

## 2.3 OOTB

官方入口：

1. 数据集仓库：<https://github.com/YZCU/OOTB>

官方页面确认的信息：

1. 它是卫星视频 **单目标跟踪** benchmark
2. 共 `110` 个视频序列
3. 共 `29,890` 帧
4. 采用 oriented bounding box 标注

### 官方公开指标类型

OOTB 官方 README 和 benchmark 说明强调的是：

1. `Precision`
2. `Normalized Precision`
3. `Success`

也就是说：

1. 它不是多目标 MOT benchmark
2. 它不以 `MOTA / IDF1` 为主指标

### 是否有公开模型

OOTB 官方仓库确认公开了：

1. 数据集
2. benchmark toolkit
3. benchmark 结果

并且 README 明确提到：

1. `DF` 在 OOTB / SatSOT / SV248S 上的结果已发布
2. `RAMC` 在 OOTB / SatSOT / SV248S 上的结果已发布
3. `REPS` 在 OOTB 上的结果已发布

但就仓库 README 可见信息来看：

1. **公开 benchmark 结果是确定的**
2. **是否有统一整理好的权重下载入口并不明确**

### 判断

1. OOTB 很适合评估卫星视频单目标鲁棒性
2. 但它不适合作为你本项目的 `MOTA / IDF1` 主验收数据

## 2.4 VisDrone: Multi-Object Tracking

官方入口：

1. 数据集仓库：<https://github.com/VisDrone/VisDrone-Dataset>
2. Challenge result paper：<https://openaccess.thecvf.com/content/ICCV2021W/VisDrone/papers/Chen_VisDrone-MOT2021_The_Vision_Meets_Drone_Multiple_Object_Tracking_Challenge_Results_ICCVW_2021_paper.pdf>

官方页面确认的信息：

1. 官方仓库提供 `VisDrone-MOT` train / val / test-dev / test-challenge
2. 任务是 UAV 多目标跟踪
3. 数据公开程度很好，下载门槛低

### 官方公开模型

VisDrone 官方仓库本身：

1. 主要提供数据
2. **没有统一官方 baseline 权重下载**

但官方 challenge result 论文公开了多个参赛方案及其框架组成：

1. `SOMOT`
2. `GIAOTracker-Fusion`
3. `MMDS`
4. `Deep IoU Tracker`
5. `Yolo-Deepsort-VisDrone`
6. `CenterPointCF`
7. `MIYoT`
8. `HNet`

论文还给了这些算法的 detector / tracker 组成，比如：

1. DeepSORT
2. FairMOT
3. DetectoRS
4. Cascade R-CNN
5. YOLOv4

### 官方指标

需要特别注意：

1. `VisDrone-MOT2021` 官方表格使用的是 `AP / AP0.25 / AP0.5 / AP0.75` 等指标
2. 冠军 `SOMOT` 的官方成绩是：
   - `AP = 58.61`
   - `AP0.25 = 70.75`
   - `AP0.5 = 61.26`
   - `AP0.75 = 43.84`

因此它虽然是 MOT 数据，但 **官方 challenge 页面和结果论文主打的不是 `MOTA / IDF1`**。

### 判断

1. 很适合做工程联调、算法预训练、候选方案筛选
2. 不适合作为你这个项目的最终遥感主验收数据

## 2.5 A2Seek

官方入口：

1. 项目页：<https://hayneyday.github.io/A2Seek/>

官方页面确认的信息：

1. 它是 aerial anomaly understanding benchmark
2. 有：
   - anomaly categories
   - frame-level timestamps
   - region-level bounding boxes
   - natural language explanations
3. 页面给出了：
   - 论文
   - 补充材料（Hugging Face）
   - 代码入口

### 是否有公开模型

官方页面至少可以确认：

1. 有公开代码入口
2. 有公开补充材料 / Hugging Face 页面

但从项目页文本上能直接确认的部分是：

1. **代码公开是明确的**
2. **是否公开了完整可直接推理的 checkpoint，需要进一步到代码仓库和 HF 页面里核实**

### 官方指标

项目页明确给出的指标描述是：

1. `A2Seek-R1` 在 anomaly prediction accuracy 上最高提升 `22.04% AP`
2. 在 anomaly localization 上提升 `13.9% mIoU`

另外，官方 Hugging Face 页面明确说明：

1. 可以在 `Preview` 文件夹中预览子集
2. 完整原始 `4K` 视频需要走额外下载入口

这意味着：

1. **A2Seek_Preview 是适合当前机器做轻量测试的**
2. **完整 A2Seek 不适合在当前资源约束下直接自动下载**

这说明 A2Seek 非常适合做异常预警模块验证，但它的官方指标体系不是 `MOTA / IDF1`。

### 判断

1. 非常适合你要的“异常事件检出 Precision”模块
2. 不适合作为 MOT 主评估集

## 3. 横向对比

| 数据集 | 场景 | 官方主任务 | 官方主指标 | 是否有公开模型/代码 | 与本项目匹配度 |
| --- | --- | --- | --- | --- | --- |
| VISO | 卫星视频 | 检测 / SOT / MOT | 需结合 SatVideoDT 看 | 有公开数据；公开强相关模型 MP2Net | 高 |
| SatVideoDT | 卫星视频 | 检测 / SOT / MOT | `mAP` / `DPR` / `OSR` / `MOTA` / `IDF1` | 有公开工具；有公开强相关模型 MP2Net | 最高 |
| OOTB | 卫星视频 | SOT | `Precision / NPrecision / Success` | 有公开 benchmark；权重公开不完整 | 中 |
| VisDrone-MOT | UAV 视频 | MOT | `AP` 系列 | 数据公开，竞赛方案信息公开，权重不统一 | 中 |
| A2Seek | UAV 异常视频 | 异常理解 / 定位 | `AP / mIoU` | 代码与补充材料公开 | 高（仅预警） |

## 4. 我给你的建议

### 如果当前只允许下载小于 1 GB 的测试数据

选：

1. **A2Seek_Preview**

配套补充：

1. `WALDO30_yolov8n_640x640.pt`
2. `SatVedioDTkit`

原因：

1. `A2Seek_Preview` 官方公开且体量明确，约 `200.57 MB`
2. `WALDO30` 轻量权重约 `6.00 MB`
3. 这三项合起来就能支撑“预警模块轻量测试 + BoT-SORT 工程联调 + 评估工具准备”
4. `VISO / SatVideoDT / OOTB / VisDrone-MOT` 都更适合后续在资源更充足的机器上做正式评估

### 如果你要选 1 套主数据做跟踪验收

选：

1. **SatVideoDT**

原因：

1. 官方就有多目标跟踪
2. 官方就用 `MOTA / IDF1`
3. 与你的指标定义完全对齐

### 如果你要选 1 套补充遥感数据

选：

1. **VISO**

原因：

1. 与 SatVideoDT 同源、同类
2. 更适合作为额外验证和数据扩展

### 如果你要选 1 套预警数据

选：

1. **A2Seek**

原因：

1. 异常定义更完整
2. 有时序区间和区域框
3. 能直接帮助你做异常检出 Precision

### 不建议作为主验收的

1. `OOTB`
   - 因为它是 SOT，不是 MOT
2. `VisDrone-MOT`
   - 因为它不是卫星遥感，而且官方主指标和你的验收指标并不完全一致
