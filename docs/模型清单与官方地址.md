# GeoView 模型清单与官方地址

本文档整理当前 GeoView 仓库中**实际参与运行或可被页面选择的模型/算法**，并给出对应的本地路径、后端框架、用途，以及官方地址。

## 1. 统计范围

本文档覆盖以下两类内容：

1. 当前统一放在 `backend/model/<页面>/<模型名>/` 下的可选模型目录
2. 这些模型实际依赖的上游框架、官方模型页或官方算法文档

说明：

1. 本项目中很多权重是**本地导出的推理模型**或**项目内部训练/微调后的 checkpoint**。
2. 对这类模型，下面的“官方地址”指向的是它的**官方上游模型/框架来源**，不代表仓库中的 checkpoint 一定与官方发布权重完全一致。
3. `backend/model/mmseg_config/` 目前不是当前统一路径方案下的在用模型目录，可视为历史遗留，不计入本清单。

## 3. 各模型的仓库内依据

下面列出各模型在仓库中的直接依据，方便排查。

### 3.1 Paddle 导出模型

这几类模型通过 `model.yml / pipeline.yml / model.pdmodel / model.pdiparams` 识别：

1. `backend/model/change_detection/bit_256x256`
2. `backend/model/classification/resnet50`
3. `backend/model/object_detection/paddle_yolo`
4. `backend/model/semantic_segmentation/paddle_deeplabv3p`

对应的 `model.yml` 中模型名分别是：

1. `BIT`
2. `ResNet50_vd`
3. `PPYOLO`
4. `DeepLabV3P`

### 3.2 Hugging Face 模型

这几类模型通过 `hf_config.json` 识别：

1. `backend/model/object_detection/hf_detr_resnet50`
2. `backend/model/object_detection/hf_conditional_detr_resnet50`
3. `backend/model/object_detection/hf_waldo30`
4. `backend/model/image_restoration/hf_swin2sr_x2`
5. `backend/model/image_restoration/hf_swin2sr_x4`

对应的 `model_id` 分别是：

1. `facebook/detr-resnet-50`
2. `microsoft/conditional-detr-resnet-50`
3. `StephanST/WALDO30`
4. `caidas/swin2SR-classical-sr-x2-64`
5. `caidas/swin2SR-classical-sr-x4-64`

### 3.3 MMRotate 模型

当前在用的 MMRotate 模型目录：

1. `backend/model/object_detection/mmrotate_oriented_rcnn_r50_fpn_1x_dota_le90`

依据：

1. 目录内存在 `config.py`
2. 目录内存在 `checkpoint.pth`
3. `model_manifest.json` 中标记 `backend: mmrotate`

### 3.4 MMSegmentation 模型

当前在用的 MMSeg 模型目录：

1. `backend/model/semantic_segmentation/mmseg_cugrs`

依据：

1. 目录内存在 `config.py`
2. 目录内存在 `checkpoint.pth`
3. `model_manifest.json` 中标记 `backend: mmsegmentation`

该模型的配置中还显式依赖了以下支持权重：

1. `backend/model/semantic_segmentation/mmseg_cugrs/support/dinov3_vitl16_pretrain_sat493m-eadcf0ff.pth`
2. `backend/model/semantic_segmentation/mmseg_cugrs/support/swin_base_patch4_window7_224_20220317-e9b98025.pth`

需要注意：

1. `dinov3_vitl16_pretrain_sat493m-eadcf0ff.pth` 的文件名显示它是 DINOv3 ViT-L/16 相关的本地支持权重，但是否与上游官方公开权重一一对应，需要以实际来源为准。
2. `mmseg_cugrs/checkpoint.pth` 是本项目自己的可运行分割 checkpoint，不是 MMSeg 官方模型库里的原样 checkpoint。

### 3.5 配准与跟踪算法目录

这几类目录是**算法运行入口**，不一定都有深度权重文件：

1. `backend/model/registration/auto`
2. `backend/model/registration/opencv`
3. `backend/model/registration/loftr_outdoor`
4. `backend/model/tracking/auto`
5. `backend/model/tracking/csrt`
6. `backend/model/tracking/kcf`

它们主要通过 `model_manifest.json` 中的 `backend` 与 `runtime` 字段被识别。

## 4. 特别说明

### 4.1 哪些是“官方模型页”，哪些只是“官方框架页”

可直接给出官方模型页的：

1. Hugging Face 模型
2. LoFTR
3. OpenCV 跟踪器 / 特征算法文档

更适合给“官方框架/官方仓库”地址的：

1. Paddle 导出模型
2. MMRotate 本地 checkpoint
3. MMSeg 本地 checkpoint

原因是这几类模型在仓库中使用的是**本地导出**或**内部训练后的权重**，不是官方站点上一模一样的原始发布包。

### 4.2 当前项目里的自定义模型代码

仓库中还存在以下自定义模型代码：

1. `backend/model/custom_models/dinov3.py`
2. `backend/model/custom_models/dinov3swin.py`
3. `backend/model/custom_models/__init__.py`

这些属于**项目自定义实现代码**，不是独立给前端页面选择的模型目录，但会被 `mmseg_cugrs` 这类组合模型使用。

### 4.3 与页面分布的对应关系

当前页面分布下的模型目录如下：

1. 变化检测：`backend/model/change_detection/*`
2. 地物分类：`backend/model/classification/*`
3. 目标检测：`backend/model/object_detection/*`
4. 语义分割 / 多要素地物分类：`backend/model/semantic_segmentation/*`
5. 图像修复 / 超分：`backend/model/image_restoration/*`
6. 配准：`backend/model/registration/*`
7. 跟踪：`backend/model/tracking/*`

## 5. 建议后续维护方式

为了让这份清单以后不失效，建议后续新增模型时同时补三处：

1. 新模型目录下补 `model_manifest.json` 或 `hf_config.json`
2. 在后端模型路由里补到统一映射
3. 同步更新本文档中的“本地目录 / 官方地址 / 说明”
