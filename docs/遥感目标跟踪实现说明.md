# 遥感目标跟踪实现说明

## 1. 实现目标

本次实现为 GeoView 增加了一个可落地的“遥感图像序列单目标跟踪”能力，目标是先把项目内的上传、分析、结果展示、历史记录这条工程链路闭环，而不是在当前阶段引入一套高耦合、重量级、需要额外权重管理和训练框架的大模型栈。

本实现的输入假设如下：

- 输入为按时间顺序命名的图像序列，而不是前端直接上传视频。
- 用户在前端首帧上框选一个初始目标框。
- 后端输出跟踪预览图、结果视频、轨迹 JSON 和统计摘要。

之所以采用这个边界，是因为项目现有 `/api/file/upload` 上传层只支持图片与 TIFF，不支持直接上传视频；因此本次实现优先复用现有上传协议和历史记录模型，避免另开一套上传与存储逻辑。

## 2. 实现方案

### 2.1 总体架构

整体链路调整为两段式：

1. 前端通过 `/api/file/upload` 上传图像序列。
2. 前端按文件名自然排序后，使用 JSON 调用 `/api/analysis/tracking`。
3. 后端在 Python 中执行单目标跟踪，生成：
   - 标注结果视频
   - 三时相拼接预览图
   - 逐帧轨迹 JSON
   - 统计摘要
4. 历史记录保留首帧图和预览图，视频/轨迹路径写入 `data` 字段，历史页可直接打开结果视频。

### 2.2 跟踪算法设计

实现选用了当前仓库最容易维护的开源工具组合：

- OpenCV Tracking API 作为主跟踪器实现。
- `CSRT` 作为默认优先方案。
- `KCF` / `MIL` 作为自动回退方案。
- 基于模板匹配的局部纠偏，用于降低纯相关滤波器在遥感小目标、弱纹理或轻微平台抖动下的漂移风险。
- 当运行环境缺少 OpenCV Tracker contrib 模块时，自动退化为纯模板匹配基线，避免接口直接不可用。

后端执行逻辑如下：

1. 按文件名自然排序序列帧。
2. 首帧按用户框选初始化目标。
3. 若原图过大，先按最长边缩放到 1280 像素以内做跟踪，控制 CPU 开销。
4. 每一帧先运行 OpenCV 跟踪器得到候选框。
5. 再在局部搜索窗或全局区域上做模板匹配，得到一个纠偏框和置信度。
6. 当纠偏结果可靠时，重新初始化跟踪器并更新模板。
7. 如果当前 Python/OpenCV 环境没有 `TrackerCSRT/KCF/MIL`，则直接退化为模板匹配跟踪，不阻断前后端流程。
7. 输出逐帧 `bbox`、`confidence`、`tracked` 状态。

### 2.3 针对遥感场景的工程处理

为了让该基线更适合遥感序列而不是普通短视频，本次加了几项工程增强：

- 支持 TIFF 及常见遥感图像格式读取。
- 对多波段 TIFF 做稳健归一化后再转成三通道可视化图像。
- 在跟踪时对灰度图做 CLAHE + 轻量锐化，提升小目标可分性。
- 使用模板匹配做轻量级纠偏，缓解卫星平台抖动和目标尺寸较小时的漂移。
- 结果不仅输出视频，还输出轨迹 JSON，便于后续接多目标评估或回放分析。

## 3. 前后端接口约定

### 3.1 请求格式

`POST /api/analysis/tracking`

示例：

```json
{
  "model_path": "builtin:tracking:auto",
  "list": [
    {
      "src": "/_uploads/photos/frame_0001.png",
      "filename": "frame_0001.png"
    },
    {
      "src": "/_uploads/photos/frame_0002.png",
      "filename": "frame_0002.png"
    }
  ],
  "rect": [512, 364, 48, 36]
}
```

### 3.2 返回格式

成功时返回：

```json
{
  "status": "success",
  "method_used": "opencv_csrt",
  "first_frame_input": "/_uploads/photos/frame_0001.png",
  "preview_path": "/_uploads/photos/res/xxx_preview.png",
  "output_video_path": "/_uploads/photos/res/xxx_sequence.mp4",
  "trajectory_path": "/_uploads/photos/res/xxx_trajectory.json",
  "summary": {
    "total_frames": 60,
    "tracked_frames": 57,
    "lost_frames": 3,
    "tracking_ratio": 0.95,
    "mean_confidence": 0.73,
    "center_displacement": 128.46
  }
}
```

## 4. 关键文件变更

- `backend/applications/api/model.py`
  - 新增 `builtin:tracking:auto`、`builtin:tracking:csrt`、`builtin:tracking:kcf` 模型入口，并明确自动回退策略。
- `backend/applications/api/analysis.py`
  - 将 tracking 接口改为接收图像序列列表和初始框。
- `backend/applications/interface/analysis.py`
  - 调整 tracking 调用签名，落库首帧、预览图以及视频/轨迹元数据。
- `backend/applications/interface/tracking.py`
  - 新增完整的 Python 跟踪执行逻辑，并补齐“无 contrib Tracker 时退化到模板匹配”的兜底路径。
- `backend/requirements.txt`
  - 将主服务环境中的 OpenCV 依赖切换到 `opencv-contrib-python`，保证 Docker / 正式部署环境具备 CSRT/KCF/MIL 跟踪器。
- `backend/requirements-hf.txt`
  - 补齐 registration 相关的 `kornia`、`kornia_moons`、`opencv-contrib-python`、`scipy`、`matplotlib` 依赖说明，避免文档依赖与实际实现脱节。
- `frontend/src/views/mainfun/Tracking.vue`
  - 重写页面流程，切换为“上传图像序列 -> 选择首帧目标框 -> 请求分析 -> 展示预览图/视频/轨迹”，并补齐错误提示与结果 URL 处理。
- `frontend/src/views/history/History.vue`
  - 为 tracking 历史记录增加结果视频打开与视频下载能力。

## 5. Docker / 依赖变更

本次实现区分为“Docker 配置文件”与“镜像内依赖声明”两个层面：

- `docker-compose.yml` 不需要修改。
- `Dockerfile` 也不需要直接修改。
- 但依赖文件需要同步更新：
  - `backend/requirements.txt`
  - `backend/requirements-hf.txt`

原因如下：

- 后端主服务镜像已经通过 `Dockerfile` 执行 `pip install -r backend/requirements.txt`，因此只要依赖文件更新，重新构建镜像即可同步到容器，无需额外改 compose。
- registration 的 Docker 主流程里已经显式创建 `HFPyTorch310` 并安装 Kornia 相关依赖，因此不需要再改容器编排参数；本次主要是把 `backend/requirements-hf.txt` 文档化依赖补齐，避免“实现已用到，但依赖清单未记录”的问题。
- tracking 新实现虽然加了模板匹配兜底，但为了保证 `CSRT/KCF/MIL` 这条主路径在标准部署里稳定可用，仍需要将主服务依赖从 `opencv-python` 同步到 `opencv-contrib-python`。
- 本次没有新增端口、卷挂载、环境变量，也没有新增独立服务。

换句话说，本次需要的是“镜像依赖同步”，而不是“Docker 编排结构改动”。

## 8. 当前边界与后续建议

本次实现是一个工程基线，不是遥感 SOTA 跟踪器。当前仍有以下边界：

- 仅支持单目标跟踪。
- 依赖用户首帧手工框选。
- 更适合短序列或中等长度序列的稳定跟踪。
- 对严重遮挡、目标完全消失后重识别、剧烈尺度变化还不够强。
- 若部署环境缺少 `opencv-contrib-python`，系统会退化到模板匹配兜底，功能仍可用，但鲁棒性低于 CSRT/KCF 主路径。

如果后续要继续增强，建议优先做：

1. 引入专门的遥感单目标跟踪模型接口，例如面向卫星视频的 Siamese / Transformer 跟踪器。
2. 增加“丢失后重检测”能力，而不是只依赖模板匹配纠偏。
3. 在历史页增加轨迹回放或 JSON 可视化能力。
4. 在数据层引入 VISO / OOTB / SatVideoDT 小规模验证集，形成最基本的回归评估。
