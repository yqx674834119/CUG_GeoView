# GeoView 完整压缩包交付手册

本手册只保留一条交付路线：

1. 构建整项目主镜像
2. 推送到阿里云镜像仓库
3. 在中转机器拉取该镜像并导出为 `.tar`
4. 将“项目代码目录 + 主镜像 tar + 本手册”打成一个完整压缩包

这份手册刻意不包含以下内容：

- 前端单独镜像交付
- 前端 Helm 包交付
- 整项目 Helm 包交付

如果后续仍然需要这些产物，请放到项目仓库外部管理，不要再放回本项目目录。

## 3. 重新构建并推送主镜像

以下步骤在联网构建机执行。

### 3.1 登录阿里云镜像仓库

```bash
docker login --username=13997543646yqx crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com
```

### 3.2 构建最终交付镜像

整项目镜像现在直接由根目录 `Dockerfile` 构建：

```bash
export BUILD_DATE=$(date +%Y%m%d)
export APP_IMAGE=crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com/shawnyao/cugrs
export APP_VERSION=${BUILD_DATE}

docker build \
  -f Dockerfile \
  -t "${APP_IMAGE}:${APP_VERSION}" \
  -t "${APP_IMAGE}:latest" \
  .
```

如果你就是要完全复刻历史上的“覆盖 latest”行为，上面第二个 tag 不能省。

### 3.3 本地自检

至少做这几项确认：

```bash
docker images | grep 'shawnyao/cugrs'
docker run --rm "${APP_IMAGE}:latest" python -V
docker run --rm "${APP_IMAGE}:latest" bash -lc 'ls /app && test -f /usr/local/bin/entrypoint.sh'
```

如需更接近正式运行环境，可再用 [docker-compose.yml](/home/livablecity/GeoView/docker-compose.yml:1) 做一次联调，但这一步不是“重新打包”本身的必需条件。

### 3.4 推送到阿里云

```bash
docker push "${APP_IMAGE}:${APP_VERSION}"
docker push "${APP_IMAGE}:latest"
```

建议同时保留版本号标签和 `latest`：

- 版本号标签便于回溯
- `latest` 便于保持历史交付习惯

## 4. 在中转机器导出主镜像 tar

以下步骤在中转机器执行。

### 4.1 拉取主镜像

```bash
export APP_IMAGE=crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com/shawnyao/cugrs:latest
docker pull "${APP_IMAGE}"
```

如果你想固定某个版本，就把 `latest` 换成 `:${APP_VERSION}`。

### 4.2 导出 tar

建议导出到项目目录外，避免再次污染仓库：

```bash
mkdir -p ~/geoview-delivery-artifacts

docker save \
  -o ~/geoview-delivery-artifacts/crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com_shawnyao_cugrs_latest.tar \
  "${APP_IMAGE}"
```

导出后可校验一下：

```bash
ls -lh ~/geoview-delivery-artifacts/
docker image inspect "${APP_IMAGE}" >/dev/null
```

## 5. 生成最终完整压缩包

这里的目标不是单独交镜像，而是交一个完整压缩包。

推荐最终结构如下：

```text
GeoView_Full_Delivery_YYYYMMDD/
├── GeoView/
├── images/
│   └── crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com_shawnyao_cugrs_latest.tar
└── docs/
    └── 完整压缩包交付手册.md
```

### 5.1 组装交付目录

仍然建议在项目目录外操作：

```bash
export DELIVERY_DATE=$(date +%Y%m%d)
export DELIVERY_ROOT=~/geoview-delivery-artifacts/GeoView_Full_Delivery_${DELIVERY_DATE}

mkdir -p "${DELIVERY_ROOT}/images"
mkdir -p "${DELIVERY_ROOT}/docs"
```

复制主镜像 tar：

```bash
cp \
  ~/geoview-delivery-artifacts/crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com_shawnyao_cugrs_latest.tar \
  "${DELIVERY_ROOT}/images/"
```

复制手册：

```bash
cp docs/完整压缩包交付手册.md "${DELIVERY_ROOT}/docs/"
```

复制项目代码目录。推荐用 `rsync`，并显式排除仓库内的临时产物：

```bash
rsync -a \
  --exclude '.git' \
  --exclude '__pycache__' \
  --exclude 'node_modules' \
  --exclude 'deploy/frontend/dist' \
  --exclude 'deploy/frontend/helm/dist' \
  --exclude 'deploy/helm/dist' \
  --exclude '*.tar' \
  --exclude '*.tar.gz' \
  --exclude '*.tgz' \
  --exclude '*.zip' \
  ./ "${DELIVERY_ROOT}/GeoView/"
```

### 5.2 打成最终压缩包

```bash
cd ~/geoview-delivery-artifacts
tar -czf "GeoView_Full_Delivery_${DELIVERY_DATE}.tar.gz" "GeoView_Full_Delivery_${DELIVERY_DATE}"
```

完成后，你真正对外交付的是这个文件：

```text
~/geoview-delivery-artifacts/GeoView_Full_Delivery_YYYYMMDD.tar.gz
```

## 6. 接收方怎么使用

接收方拿到完整压缩包后，最小流程如下：

### 6.1 解压

```bash
tar -xzf GeoView_Full_Delivery_YYYYMMDD.tar.gz
cd GeoView_Full_Delivery_YYYYMMDD
```

### 6.2 导入主镜像

```bash
docker load -i images/crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com_shawnyao_cugrs_latest.tar
```

### 6.3 进入项目目录启动

```bash
cd GeoView
docker compose up -d
```

如果目标机器需要 GPU，请先准备好 NVIDIA 驱动和 Container Toolkit。

## 7. 这次交付明确不要什么

这次交付中，以下内容不要再作为项目内交付产物保留：

- 前端单独镜像 tar
- 前端 Helm 包
- 整项目 Helm 包
- Harbor values 示例包
- 中转打包脚本生成的 dist 压缩包

如果将来业务上确实还要保留这些路线，也建议把产物统一输出到仓库外部目录，例如：

```text
~/geoview-delivery-artifacts/
```

而不是继续堆在项目根目录或 `deploy/**/dist/` 下面。

## 8. 推荐的最终习惯

以后如果你还沿用这套交付方式，建议固定成下面这条流程：

1. 在构建机只用 `Dockerfile` 构建主镜像
2. 推送到阿里云仓库，至少同时保留一个版本 tag 和一个 `latest`
3. 在中转机器 `docker pull`
4. 在中转机器 `docker save`
5. 在项目目录外组装并压缩完整交付包

这样项目仓库本身只保留源码和运行配置，不再积累一堆交付副产物。
