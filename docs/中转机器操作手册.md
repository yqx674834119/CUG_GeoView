# GeoView 中转机器操作手册

这份文档是给“联网中转同事”直接使用的。

你的任务很简单：

1. 把 `Thin 包` 变成 `Full 包`
2. 把 `Full 包` 拷到移动硬盘
3. 交给内网 Helm 部署同事

你不需要负责最终 Helm 平台部署。

## 1. 你会收到什么

你会收到：

1. 一个压缩包：`GeoView_Offline_Thin_YYYYMMDD.tar.gz`
2. GeoView 应用镜像地址
3. 如果镜像仓库是私有的，还会收到账号密码

你最终要交回的文件是：

```text
GeoView_Offline_Full_YYYYMMDD.tar.gz
```

## 2. 你的机器需要满足什么条件

中转机器必须满足：

1. 可以联网
2. 安装了 Docker
3. 安装了 Docker Compose 插件
4. 磁盘空间尽量充足

先执行：

```bash
docker --version
docker compose version
```

如果这两条命令都正常输出版本号，就可以继续。

## 3. 本次要用的镜像地址

GeoView 应用镜像地址：

```text
crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com/shawnyao/cugrs:latest
```

MySQL 镜像地址：

```text
registry.openanolis.cn/openanolis/mysql:8.0.30-8.6
```

## 4. 如果需要，先登录阿里云镜像仓库

如果系统提示没有权限拉取镜像，请先登录。

登录命令示例：

```bash
docker login --username=你的账号 crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com
```

如果你已经登录过，可以跳过这一步。

## 5. 第一步：把 Thin 包放到一个独立目录

比如：

```bash
~/delivery/
```

假设你收到的文件已经放在这里：

```text
~/delivery/GeoView_Offline_Thin_YYYYMMDD.tar.gz
```

## 6. 第二步：解压 Thin 包

执行：

```bash
cd ~/delivery
tar -xzf GeoView_Offline_Thin_*.tar.gz
cd GeoView
```

进入 `GeoView` 目录后，你应该至少能看到这些文件：

1. `deploy_offline.sh`
2. `export_offline.sh`
3. `docker-compose.yml`
4. `backend/`
5. `offline_cache/`
6. `backend/model/`

## 7. 第三步：启动中转环境

确保你当前就在 `GeoView` 目录里，然后执行：

```bash
./deploy_offline.sh
```

这条命令会自动做这些事情：

1. 整理 `offline_cache/` 目录
2. 从 `backend/model/` 生成运行时缓存
3. 检查模型文件是否完整
4. 自动拉取 GeoView 应用镜像
5. 自动拉取 MySQL 镜像
6. 启动 GeoView 容器和 MySQL 容器

这一步可能要等几分钟，属于正常现象。

## 8. 第四步：检查系统是否启动成功

先看容器状态：

```bash
docker compose ps
```

如果你看到：

1. `cugrs-app` 是 `Up`
2. `cugrs-mysql` 是 `Up`

就说明容器已经启动成功。

再看一下应用日志：

```bash
docker logs -f cugrs-app
```

如果没有持续报错，按：

```text
Ctrl + C
```

退出日志查看。

如果机器带桌面环境，也可以用浏览器打开：

```text
http://127.0.0.1:3000
```

页面能打开，说明这一步基本成功。

## 9. 第五步：导出 Full 包

确认系统已经能正常启动后，仍然在 `GeoView` 目录里执行：

```bash
./export_offline.sh 1
```

这一步会把完整内容打出来，包括：

1. 项目代码
2. `backend/model/`
3. `offline_cache/`
4. 离线镜像合集：`offline_images/geoview_images.tar`
5. Helm 相关目录和脚本

这一步通常也会比较久，请耐心等待。

## 10. 第六步：找到生成好的 Full 包

Full 包不在当前 `GeoView` 目录里，而是在它的上一级目录。

如果你当前目录是：

```text
~/delivery/GeoView
```

那最终生成结果通常在：

```text
~/delivery/GeoView_Offline_Full_YYYYMMDD.tar.gz
```

你可以执行：

```bash
cd ..
ls -lh GeoView_Offline_Full_*.tar.gz
```

确认它已经生成。

## 11. 第七步：把 Full 包拷到移动硬盘

你最后只需要拷走这一个文件：

```text
GeoView_Offline_Full_YYYYMMDD.tar.gz
```

不要只拷：

1. `GeoView/` 文件夹
2. `offline_images/`
3. `backend/model/`

必须拷完整的：

```text
GeoView_Offline_Full_YYYYMMDD.tar.gz
```

## 12. 做完后交给谁

把 `GeoView_Offline_Full_YYYYMMDD.tar.gz` 交给内网 Helm 部署同事。

他下一步要参考这份文档：

- [Full包转Helm部署操作手册](/home/livablecity/GeoView/docs/Full包转Helm部署操作手册.md)

## 13. 你最容易犯的 4 个错误

1. 不要在中转机器再次执行 `./export_offline.sh 2`
说明：中转机器的目标是生成 `Full 包`，所以这里必须执行 `./export_offline.sh 1`

2. 不要在导出 Full 包之前直接关闭容器
说明：缓存同步逻辑会优先从运行中的 `cugrs-app` 容器抓取运行时缓存

3. 如果 `deploy_offline.sh` 拉镜像失败，先检查镜像仓库登录状态
说明：大多数“无权限拉取镜像”都是登录问题

4. 交回时不要只交文件夹，必须交回完整的 `GeoView_Offline_Full_YYYYMMDD.tar.gz`

## 14. 给你的最短执行版

如果你已经看完上面的说明，可以按这个最短顺序执行：

```bash
cd ~/delivery
tar -xzf GeoView_Offline_Thin_*.tar.gz
cd GeoView
./deploy_offline.sh
docker compose ps
docker logs -f cugrs-app
./export_offline.sh 1
cd ..
ls -lh GeoView_Offline_Full_*.tar.gz
```
