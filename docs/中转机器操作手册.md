# GeoView 中转机器操作手册

注意：

- 这份文档里包含阿里云镜像仓库账号密码
- 只允许在内部交付使用
- 如果后续密码改了，这份文档也要一起更新


## 你会收到什么

你会收到以下内容：

1. 一个压缩包：`GeoView_Offline_Thin_YYYYMMDD.tar.gz`
2. 这份操作文档

你的任务只有一件事：

把 `Thin 包` 变成 `Full 包`，然后把 `Full 包` 交回去。

## 你最终要交回什么

你最后只需要交回这一个文件：

```text
GeoView_Offline_Full_YYYYMMDD.tar.gz
```

## 你的机器需要满足什么条件

中转机器必须满足：

1. 可以联网
2. 安装了 Docker
3. 安装了 Docker Compose 插件
4. 磁盘空间尽量充足

先打开终端，执行：

```bash
docker --version
docker compose version
```

如果这两条命令都能正常输出版本号，就可以继续。

## 一步一步操作

### 第 1 步：把 Thin 包放到一个单独目录

比如你可以放到：

```bash
~/delivery/
```

假设你已经把文件放好了：

```text
~/delivery/GeoView_Offline_Thin_YYYYMMDD.tar.gz
```

### 第 2 步：解压 Thin 包

执行：

```bash
cd ~/delivery
tar -xzf GeoView_Offline_Thin_*.tar.gz
cd GeoView
```

进入 `GeoView` 后，你应该能看到这些文件：

- `deploy_offline.sh`
- `export_offline.sh`
- `docker-compose.yml`
- `backend/`
- `docs/`

### 第 3 步：登录阿里云镜像仓库

执行：

```bash
docker login --username=13997543646yqx crpi-4r2gidb79yjyny4o.cn-hangzhou.personal.cr.aliyuncs.com
```

输入密码：

```text
Yqx123123123
```

如果看到 `Login Succeeded`，说明登录成功。

### 第 4 步：启动中转环境

确保你当前就在 `GeoView` 目录里，然后执行：

```bash
./deploy_offline.sh
```

这个命令会自动做这些事情：

1. 检查和修正 `offline_cache/` 目录权限
2. 从 `backend/model/` 生成运行时缓存
3. 检查模型文件是否完整
4. 自动拉取 GeoView 应用镜像
5. 自动拉取 MySQL 镜像
6. 启动 GeoView 和 MySQL 容器

这一步可能要等几分钟，属于正常现象。

### 第 5 步：检查系统是否启动成功

先看容器状态：

```bash
docker compose ps
```

如果你看到：

- `cugrs-app` 是 `Up`
- `cugrs-mysql` 是 `Up`

就说明容器启动成功了。

然后再看一下日志：

```bash
docker logs -f cugrs-app
```

如果没有一直报错，按：

```bash
Ctrl + C
```

退出日志查看。

### 第 6 步：用浏览器简单确认一下

在中转机器浏览器打开：

```text
http://127.0.0.1:3000
```

如果页面能打开，说明这一步基本没问题。

### 第 7 步：导出 Full 包

确认系统已经能正常启动后，回到终端，仍然在 `GeoView` 目录里，执行：

```bash
./export_offline.sh 1
```

这一步会把完整内容打包出来，包括：

1. 项目代码
2. 统一模型目录 `backend/model/`
3. 运行缓存 `offline_cache/`
4. GeoView 应用镜像 tar
5. MySQL 镜像 tar

这一步通常也会比较久，请耐心等待。


### 第 8 步：找到生成好的 Full 包

Full 包不会放在当前 `GeoView` 目录里，而是放在它的上一级目录。

如果你当前目录是：

```text
~/delivery/GeoView
```

那么生成结果通常在：

```text
~/delivery/GeoView_Offline_Full_YYYYMMDD.tar.gz
```

你可以执行：

```bash
cd ..
ls -lh GeoView_Offline_Full_*.tar.gz
```

确认文件已经生成。

不要只交回 `backend/model/`。

必须交回完整的 `GeoView_Offline_Full_YYYYMMDD.tar.gz`。

## 做完后的成功标准

只要满足下面 3 条，就算中转成功：

1. `./deploy_offline.sh` 执行成功
2. `docker compose ps` 里 `cugrs-app` 和 `cugrs-mysql` 都是 `Up`
3. 上一级目录里出现了 `GeoView_Offline_Full_YYYYMMDD.tar.gz`

## 最终离线机器如何使用 Full 包

下面这部分是给“最终离线机器同事”使用的。

如果中转机器已经生成了：

```text
GeoView_Offline_Full_YYYYMMDD.tar.gz
```

那么最终离线机器只需要拿到这一个文件，就可以部署。

注意：

- 最终离线机器不需要联网
- 不需要再登录阿里云
- 不需要再单独拉镜像
- 不需要再执行 `export_offline.sh`

最终离线机器只做“解压 + 部署”两件事。

### 最终离线机器需要满足什么条件

最终离线机器必须满足：

1. 安装了 Docker
2. 安装了 Docker Compose 插件
3. 磁盘空间足够

先执行：

```bash
docker --version
docker compose version
```

如果这两条命令都正常，就可以继续。

### 第 1 步：把 Full 包复制到最终离线机器

把下面这个文件复制到最终离线机器：

```text
GeoView_Offline_Full_YYYYMMDD.tar.gz
```

比如放到：

```bash
~/delivery/
```

### 第 2 步：解压 Full 包

执行：

```bash
cd ~/delivery
tar -xzf GeoView_Offline_Full_*.tar.gz
cd GeoView
```

进入 `GeoView` 后，应该可以看到这些内容：

- `deploy_offline.sh`
- `offline_images/`
- `offline_cache/`
- `backend/model/`
- `docker-compose.yml`

其中最关键的是：

- `offline_images/cugrs_app.tar`
- `offline_images/mysql.tar`

### 第 3 步：执行离线部署

在 `GeoView` 目录里执行：

```bash
./deploy_offline.sh
```

这一步会自动完成：

1. 检查缓存目录权限
2. 从 `backend/model/` 生成运行时缓存
3. 校验模型资产是否完整
4. 从 `offline_images/` 加载应用镜像和 MySQL 镜像
5. 自动启动容器

因为 Full 包里已经带了镜像 tar，所以这一步不需要联网。

### 第 4 步：检查是否启动成功

先看容器状态：

```bash
docker compose ps
```

正常情况下应看到：

- `cugrs-app` 是 `Up`
- `cugrs-mysql` 是 `Up`

然后看一下应用日志：

```bash
docker logs -f cugrs-app
```

如果没有一直报错，按：

```bash
Ctrl + C
```

退出日志查看。

### 第 5 步：打开系统

在最终离线机器浏览器访问：

```text
http://127.0.0.1:3000
```

常用端口如下：

- GeoView 前端：`3000`
- GeoView 后端：`5008`
- Miner 前端：`4000`
- Miner 后端：`8000`
- MySQL：`3307`

### 最终离线机器最短命令版

可以直接执行：

```bash
cd ~/delivery
tar -xzf GeoView_Offline_Full_*.tar.gz
cd GeoView
./deploy_offline.sh
docker compose ps
```

### 最终离线机器成功标准

只要满足下面 3 条，就说明最终离线部署成功：

1. `./deploy_offline.sh` 执行成功
2. `docker compose ps` 显示 `cugrs-app` 和 `cugrs-mysql` 都是 `Up`
3. 浏览器能打开 `http://127.0.0.1:3000`
