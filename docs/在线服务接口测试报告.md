# 在线服务接口测试报告

## 1. 测试结论

本次基于 Docker 运行环境对新增在线服务接口进行了实际联调测试。

结论如下：

- `GET /api/v1/api/service/list`：通过
- `POST /api/v1/api/task/model/deploy`：通过，占位返回“暂未实现”
- `POST /api/v1/api/service/restart`：通过
- `POST /api/v1/api/service/stop`：通过
- `POST /api/v1/api/service/update`：通过
- `DELETE /api/v1/api/service/delete`：通过
- `GET /api/v1/api/service/detail`：通过

补充说明：

- `deploy` 当前按需求仅做占位，不执行真实部署逻辑。
- 所有测试均在 Docker 容器内运行的后端服务上完成，不是本机临时 Python 环境伪测。

## 2. 为什么之前说“缺 sqlalchemy 无法启动”

这句话指的是：

- 如果直接在宿主机用当前 `python3` 启动 `backend/app.py`，会因为缺少项目要求的 Flask/SQLAlchemy/PaddleRS 依赖链而启动失败。
- 但最终交付以 Docker 为准，所以正确测试路径应当是 Docker 容器，而不是宿主机 Python。

本次已经改为 Docker 路线完成测试，因此该问题不影响本次接口验收。

## 3. Docker 影响说明

本次 **没有修改** 以下内容：

- `Dockerfile`
- `docker-compose.yml`
- 容器镜像
- 容器环境变量

本次 **实际做过的 Docker 操作** 只有：

1. 重启现有容器 `cugrs-app`
2. 在容器内临时写入测试文件 `/app/data/online_services.json`
3. 测试完成后将该文件恢复为空数组 `[]`

说明：

- 由于 `backend` 目录以 bind mount 形式挂载到容器 `/app/backend`，新增 Python 代码只需重启容器即可生效，不需要重建镜像。

## 6. 正向测试结果

### 6.1 在线服务列表

请求：

```http
GET /api/v1/api/service/list
```

结果：

- HTTP 状态码：`200`
- 返回 `total = 2`
- 返回两条测试记录

筛选请求：

```http
GET /api/v1/api/service/list?serviceCreator=alice
```

结果：

- HTTP 状态码：`200`
- 返回 `total = 1`
- 仅返回 `serviceId = 101`

### 6.2 服务详情

请求：

```http
GET /api/v1/api/service/detail?serviceId=101
```

结果：

- HTTP 状态码：`200`
- 正确返回 `serviceId = 101` 的完整记录

### 6.3 编辑在线服务

请求：

```json
POST /api/v1/api/service/update
{
  "serviceInfoDTO": {
    "serviceId": 101,
    "serviceName": "变化检测在线服务-已更新",
    "serviceDescription": "更新后的描述",
    "serviceStatus": 3
  }
}
```

结果：

- HTTP 状态码：`200`
- 返回：`服务更新成功`
- 持久化文件中对应记录被更新

### 6.4 重启在线服务

请求：

```json
POST /api/v1/api/service/restart
{
  "serviceRestartDTO": {
    "ids": "102"
  }
}
```

结果：

- HTTP 状态码：`200`
- 返回：`服务重启成功`
- `serviceId = 102` 的 `serviceStatus` 被更新为 `1`

### 6.5 停止在线服务

请求：

```json
POST /api/v1/api/service/stop
{
  "serviceStopDTO": {
    "serviceIds": [101]
  }
}
```

结果：

- HTTP 状态码：`200`
- 返回：`服务停止成功`
- `serviceId = 101` 的 `serviceStatus` 被更新为 `2`
- `offlineServiceStatus` 被更新为 `stopped`

### 6.6 删除在线服务

请求：

```http
DELETE /api/v1/api/service/delete?ids=102
```

结果：

- HTTP 状态码：`200`
- 返回：`服务删除成功`
- 持久化文件中 `serviceId = 102` 被删除

### 6.7 新建在线服务（占位接口）

请求：

{
  "serviceInfoDTO": {
    "serviceName": "占位服务"

## 9. 后续建议

1. 若后续需要真正支持“新建在线服务”，建议将 `deploy` 从占位接口升级为“先写注册表，再异步调度实际部署”。
2. 当前在线服务接口使用文件型注册表，优点是隔离、低风险、不影响已有已测功能；若后续要长期使用，建议再迁移到独立数据库表。
3. 若要完全按照外部文档的 `ApiResult<boolean>` 风格统一，可以后续再对 `code/msg/data` 包装做一次集中规范化。
