# GeoView 当前后端模型官方数据集清单

审查日期：2026-05-13

本文档基于两部分信息整理：

1. 仓库代码审查：以 `backend/applications/api/model.py`、各模型目录下的 `model_manifest.json` / `model.yml` / `hf_config.json` / `config.py` 为准，确认“当前后端有哪些模型”“前端实际显示什么名字”“哪些目录被 `disabled` 隐藏”。
2. 联网核验：优先查官方模型卡、官方仓库、官方数据集站点；如果官方明确写了“数据集未公开”，或该条目本质上不是训练权重而是工程策略/传统算法，就明确写出来，不做强行推断。

## 1. 审查范围与结论摘要

- 当前 `backend/model/` 下共审查到 19 个实际模型/运行时目录。
- 其中 16 个目录会在当前前端模型列表接口中暴露。
- 其中 3 个目录当前被后端标记为 `disabled`，前端默认不显示：
  - `backend/model/registration/opencv`
  - `backend/model/tracking/csrt`
  - `backend/model/tracking/kcf`
- 需要特别区分三类情况：
  - 有明确官方训练数据集：如 `BIT`、`ResNet50_vd`、`PPYOLO`、`DETR`、`Conditional DETR`、`Oriented R-CNN`、`LoFTR outdoor`、`BoT-SORT 官方原始版`
  - 官方明确未公开或项目私有：如 `DeepLabV3P`、`WALDO30`、`mmseg_cugrs`
  - 不是单独训练权重，而是传统算法或工程策略：如 `registration/auto`、`registration/opencv`、`tracking/auto`、`tracking/botsort`、`tracking/csrt`、`tracking/kcf`

## 3. Paddle 模型说明

用户要求以 Paddle GeoView 官方开发文档为准，这里单独强调一下：

- 参考文档：<https://github.com/PaddleCV-SIG/GeoView/blob/release/0.1.1/docs/dev.md>
- 其中已经明确给出：
  - `BIT` 对应 `LEVIR-CD`
  - `ResNet50_vd` 对应 `UC Merced Land Use Dataset`
  - `PPYOLO` 对应 `RSOD`
  - `DeepLabV3P` 对应“未公开数据集”
- 所以 Paddle 这 4 个模型里，唯一没有公开数据集地址的不是我漏查，而是 Paddle 官方文档本身就写成了“未公开数据集”。

## 4. 需要特别注意的模型

### 4.1 `mmseg_cugrs`

- 这不是某个上游官方单模型。
- 当前仓库里的最终可运行权重是项目自定义组合模型：
  - DINOv3 支撑权重
  - Swin Transformer 支撑权重
  - UPerHead / FCNHead 分割头
- 最终训练数据集在本仓库配置里写的是 `data/yunnan_dataset`，没有公开官方数据集地址。

### 4.2 `WALDO30`

- Hugging Face 官方模型卡明确说明其训练数据是作者自己构建的：
  - synthetic
  - augmented
  - semi-synthetic
- 模型卡同时明确说当前“不打算公开发布该训练数据集”。
- 因此 `hf_waldo30`、`tracking/auto`、`tracking/botsort` 这三项都不能写出一个公开可下载的数据集地址。

### 4.3 `BoT-SORT 官方原始版（ReID）`

- 这一项和工程版 `tracking/botsort` 不能混为一谈。
- 当前后端 `tracking/botsort_official` 明确绑定的是：
  - `bytetrack_x_mot17.pth.tar`
  - `fast_reid/configs/MOT17/sbs_S50.yml`
- 所以这里应该写成 MOT17，而不是泛泛写成 “MOTChallenge”。

### 4.4 传统算法 / 工程策略条目

以下目录虽然在后端模型目录中存在，但它们不是“训练权重模型”：

- `backend/model/registration/opencv`
- `backend/model/registration/auto`
- `backend/model/tracking/auto`
- `backend/model/tracking/botsort`
- `backend/model/tracking/csrt`
- `backend/model/tracking/kcf`

对这些条目，最准确的写法不是强行填某个数据集名称，而是说明：

- 它们是传统算法、路由策略，或“跟踪器配置 + 外部检测器”的工程封装
- 因而不存在单一、可归属的官方训练数据集地址

## 5. 代码审查依据

本结论直接对应以下仓库文件：

1. `backend/applications/api/model.py`
   - 决定前端接口 `/api/model/list/<type>` 返回哪些模型
   - 决定 Paddle 模型前端展示名
   - 决定哪些 `disabled` 目录不会显示
2. `backend/model/*/*/model_manifest.json`
   - 决定非 Paddle 模型的 `model_name`、`backend`、`runtime`
3. `backend/model/*/*/model.yml`
   - 决定 Paddle 模型真实 `Model`
4. `backend/model/object_detection/mmrotate_oriented_rcnn_r50_fpn_1x_dota_le90/config.py`
   - 明确 `DOTADataset`
5. `backend/model/semantic_segmentation/mmseg_cugrs/config.py`
   - 明确 `CUGRS_DATA_ROOT=data/yunnan_dataset`
6. `backend/model/tracking/botsort_official/model_manifest.json`
   - 明确 MOT17 相关 detector / ReID 配置
