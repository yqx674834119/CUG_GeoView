说明：

1. 你已经提供了 Paddle 模型的信息，因此本文档**不再重复 Paddle 模型**。
2. 本文档主要覆盖非 Paddle 模型，包括 Hugging Face、MMRotate、MMSeg、LoFTR、OpenCV 跟踪/配准算法。
3. 如果模型是项目内微调权重，或数据集没有公开说明，我会明确标注。

## 3. 需要特别注意的地方

### 3.1 `mmseg_cugrs` 不是官方单模型

`backend/model/semantic_segmentation/mmseg_cugrs` 是项目内自定义的组合模型，目录里有：

1. `checkpoint.pth`
2. `config.py`
3. `support/dinov3_vitl16_pretrain_sat493m-eadcf0ff.pth`
4. `support/swin_base_patch4_window7_224_20220317-e9b98025.pth`

其中：

1. DINOv3 和 Swin 有上游官方来源
2. 最终 `checkpoint.pth` 是项目内训练后的权重
3. 训练数据集从配置上看是 `data/yunnan_dataset`

所以这里不能简单写成“某个公开 MMSeg 模型卡训练于某个官方数据集”。

### 3.2 `loftr_outdoor` 的数据集信息带有推断成分

当前项目目录里只有：

1. `loftr_outdoor.ckpt`
2. `model_manifest.json`

官方仓库提供了 `outdoor_ds / outdoor_ot` 两类 outdoor 权重，并明确给出 MegaDepth/ScanNet 相关数据准备说明。  
由于当前项目使用的是 `outdoor` checkpoint，我把训练数据集写为 **MegaDepth**，这是基于官方命名和仓库说明做出的合理推断。

### 3.3 OpenCV 跟踪与配准不是“数据集模型”

以下目录虽然在前端页面中作为可选项出现，但本质上不是“某个训练好的权重模型”：

1. `backend/model/registration/opencv`
2. `backend/model/registration/auto`
3. `backend/model/tracking/csrt`
4. `backend/model/tracking/kcf`
5. `backend/model/tracking/auto`
6. `backend/model/tracking/botsort`

它们对应的是传统算法、OpenCV 接口或工程组合策略，因此没有统一的“训练数据集”可以填写。
